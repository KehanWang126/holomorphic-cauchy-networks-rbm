# 服务器运行说明

目标：固定seed为12345，在同一张GPU上依次运行20D、30D的HCN和NN4MGF，共四次运行，收集训练耗时、峰值显存和最终尾概率误差。代码已打包在本仓库的 `benchmarks/`，不需要再复制NN4MGF代码。

## 1. 环境

从仓库根目录运行：

```bash
conda env create -f environment.yml
conda activate hcn-rbm
pip install -r benchmarks/requirements.txt
```

## 2. 先做短检查

```bash
CUDA_VISIBLE_DEVICES=0 python benchmarks/run.py --mode smoke --dimensions 20 30
```

这一步只训练两轮，缩小了批次，用于检查环境和代码能否正常跑完，不能作为速度或精度结论。

## 3. 测训练速度和显存

```bash
CUDA_VISIBLE_DEVICES=0 python benchmarks/run.py --mode profile --dimensions 20 30
```

两种方法保留各自原始批次，先预热10轮，再计时50轮。所有运行依次进行，每个方法使用独立进程。请在GPU没有其他计算任务时运行。显存不足时保留失败结果，不自动降低批次。

## 4. 完整训练

```bash
CUDA_VISIBLE_DEVICES=0 python benchmarks/run.py --mode full --dimensions 20 30
```

HCN为20D的25k轮和30D的50k轮；NN4MGF在两个维度均为300k轮，按论文附录A分为三个100k阶段，学习率依次从1e-3降至1e-4、1e-4降至1e-5、1e-5降至1e-6。每次更新采样16,384点（train_freq=1）。配置已写好，不需要手工修改。

原公开脚本仅启用了首个100k阶段，并设置train_freq=2；这里使用论文描述的轮数与每轮采样量，保留原训练函数。论文和已检查的公开训练代码没有注明原实验seed；12345是本次比较统一选用的seed。

长任务请通过服务器作业系统或持久终端运行。默认输出到新建的 `benchmark_runs/日期时间/`。任务中断会留下日志；当前入口不支持中断续训。

## 5. 返回什么

把本次输出目录中的 `summary.csv`、`summary.json`、各方法的 `report.json`、`tail_predictions.csv` 和日志发回即可。`endpoint.pt` 是新训练的模型，可另行保留。

输出自动记录环境、GPU型号、配置、总采样量、每步时间、测量训练时间、PyTorch峰值allocated/reserved显存和Degree 5/8误差。最终训练时间以完整运行实测为准，不由50步测试外推。
